# State of the design

The foundations are better than the product. The token layer (`apps/web/app/design-tokens/*.css` + the `@theme inline` block in `globals.css`) is coherent and deliberately reconciled against the seed; there is **zero stock Tailwind palette** anywhere in `app/` or `components/`; there is **zero hardcoded UI copy** outside message files, enforced by `tests/i18n-hardcoded.test.ts` with a literally empty allowlist; the map marker spec, `public/sw.js`, the ad/partner compliance architecture (`components/ads/ad-slot.tsx` renders nothing when unsold, the «Реклама» label is a required prop), the ConfirmButton destructive policy, and the privacy layering on the passport are all genuinely well-reasoned work with the reasoning written down. `docs/design/RECONCILIATION.md` is a real design law document, and most of its rulings were actually executed.

Three structural weaknesses, and they explain roughly 80% of the findings:

1. **The design system is documented, tested, and then bypassed.** `tests/no-hardcoded-design-values.test.ts` scans exactly three directories (`components/ui`, `lib/design`, `app/[locale]/design-system`). Everything else — the entire shell, map, passport, admin, stats, and all 53 route files — is unpoliced. Of 15 primitives, `card`, `avatar`, `map-marker` and `segmented-control` have **zero** product consumers; `Card`'s class string is retyped ~100 times by hand across 9 element types and 13 padding recipes. The product is built by copying class strings, so drift is invisible to CI and unfixable centrally.
2. **There is no vocabulary for waiting, empty, or broken.** 0 `loading.tsx`, 0 `error.tsx`, 0 `not-found.tsx`, 0 `<Suspense>` across 53 routes; 37 `notFound()` call sites that all land on Next's English default; five mutually incompatible empty-state shapes, of which the only good one is a _private, non-exported function_ inside `map-explorer.tsx`. Tab navigation gives no feedback at all. The one screen that does all four states correctly (the map) is the model nobody could import.
3. **Geometry is the recurring failure, not colour.** The seed's 44px touch floor is stated in `design_handoff/README.md` and restated in `chip.tsx`, and is missed almost everywhere a control was hand-rolled: 26px (`klasirane` sport filters, API-key revoke, training-log delete), 30px (`igrishta` sport pills), 32–34px (mobile filter trigger, roster «Отбележи», pin-picker locate, all four `profil` pills, the whole admin console), 42px (the bottom tab bar itself). 49 raw `<button>` and 55 raw `<input>` outside `components/ui`. They use the _right tokens with the wrong geometry_ — which is a much cheaper fix than a restyle, and is why the systemic section matters more than the item list.

One honest caveat about severity language below: many "P1" labels in the audit were re-scoped by verifiers. The ordering here is by user pain × reach, not by the label.

# Fix now — blocks or frustrates a first-time user

### 1. `--container-*` silently doubles every `max-w-sm/md/lg/xl` in the app

**Files:** `apps/web/app/design-tokens/spacing.css:24-27`, `apps/web/app/globals.css` (`@theme inline` block), 8 call sites listed below.
Tailwind v4 builds `max-w-*` from the same `--container-*` namespace, and the seed's unlayered `:root` beats Tailwind's `@layer theme`. Follow the C7 precedent literally: declare `--container-sm/md/lg/xl` inside the `@theme inline` block as the deliberate Tailwind scale, then rewrite the call sites to the width they actually meant — `map-explorer.tsx:921` (desktop filter sheet, currently 840px), `vhod/page.tsx:34`, `otmetka/[token]/page.tsx:42`, `sesiya/[occurrenceId]/roster/page.tsx:64`, `sesiya/[occurrenceId]/qr/page.tsx:89,115`, `design-system/page.tsx:431`, `admin/kampanii/[slug]/close-form.tsx:39`. Do this first — it changes the visual measurement of screens you are about to fix.

### 2. The focus ring is dead on every Button, IconButton and Card

**Files:** `apps/web/components/ui/button.tsx:18`, `icon-button.tsx:12`, `card.tsx:11`.
`:focus-visible { outline:none; box-shadow: var(--ring) }` lives in `@layer base`; `.shadow-xs`/`.shadow-sm`/`.shadow-float` live in `@layer utilities` and win by layer order — so `outline:none` applies and the ring is discarded. Add `focus-visible:shadow-[var(--ring)]` to the shared cva base string in all three files (the same fix `accent`, checkbox, radio and switch already carry). Do **not** move the base rule out of `@layer base` — unlayered would kill the clay accent ring at `button.tsx:24`.
